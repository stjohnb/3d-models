# Web Viewer

Detailed reference for `index.html`, `embed.html`, and the generated
standalone/OEmbed outputs. See [OVERVIEW.md](OVERVIEW.md) for how these fit
into the wider repo.

## Web Viewer (index.html)

A single-page application (no build tools, no framework) with inline CSS and
ES module JS. Pulls Three.js from a CDN via import map.

### Core Functionality

- Fetches `models.json` (generated by CI) listing all STL files grouped by
  project, with optional zip bundle references, metadata, and print time
  estimates
- Presents a persistent tree browser (left) and a stage of one to three
  viewer panes (right); models are loaded into a pane on demand rather than
  every model getting its own always-present canvas
- Renders each pane in an interactive Three.js canvas with orbit controls
- Provides download links for individual STL files and a link to the
  standalone HTML viewer per model
- For projects with 2+ models, shows a "Download All" button linking to a
  CI-generated zip bundle of all STLs in the project
- For every project, shows a "Download Source" button linking to a
  CI-generated zip of the project's git-tracked source files
- Supports fullscreen mode per pane
- Only the panes the user opens create WebGL contexts (at most three), so
  the page cost no longer grows with the model count. On first load a
  `#project/model` or `#project` hash decides what to show; in PR previews
  `changed.json` expands the modified projects and loads the first of them;
  otherwise the first project's first model is loaded
- Uses a `__BUILD_HASH__` placeholder replaced at build time with the commit
  SHA for cache busting
- Includes Open Graph, Twitter Card meta tags, and Schema.org JSON-LD
  structured data (`CollectionPage` with `3DModel` items) for SEO — the
  JSON-LD is injected at build time via a `<!-- __STRUCTURED_DATA__ -->`
  placeholder
- OEmbed `<link rel="alternate">` discovery tags are injected at build time
  via a `<!-- __OEMBED_LINKS__ -->` placeholder
- Head includes `<link rel="canonical">`, `<meta name="theme-color">`,
  `<meta name="color-scheme" content="dark">`, SVG favicon links, and
  `<link rel="manifest">` pointing to `site.webmanifest`

### Render Budget

Issue #341 — a client laptop reported the gallery page pinning its fans. All
three viewers (`index.html`, `embed.html`, standalone) previously rendered
continuously at full `requestAnimationFrame` rate whether or not anything had
changed, once per open pane, at full Retina resolution, with no GPU preference
hint. An idle page cost the same as an actively-dragged one. Four changes,
identical across the three:

- **On-demand rendering.** The loop draws a frame only when the camera moved
  (`OrbitControls`' `change` event, re-attached inside `makeControls()` since
  `resetView()` rebuilds the controls object) or when something called
  `invalidate()`. After `IDLE_FRAMES_BEFORE_SUSPEND` (90 frames, ~1.5s — long
  enough that OrbitControls' damping coast and any CSS size transition always
  finish drawing) the rAF chain cancels itself entirely. `invalidate()` restarts
  it; `pointerdown` / `wheel` / `touchstart` on the canvas are also wired to it
  as belt-and-braces wake-ups.
- **Pixel-ratio cap.** `MAX_PIXEL_RATIO = 1.5` instead of raw
  `window.devicePixelRatio`. DPR 2 quadruples fragment cost for a
  barely-visible gain; `antialias: true` (MSAA) is deliberately kept, so edges
  stay clean.
- **`powerPreference: 'low-power'`.** A hint asking the browser for the
  integrated GPU — the single biggest thermal lever on a dual-GPU laptop.
  Ignored on single-GPU machines and by some browsers; harmless there.
- **`ResizeObserver`.** `resize()` used to run inside `animate()`, reading
  `canvas.clientWidth` and forcing a layout flush every frame of every pane;
  worse, its guard compared a device-pixel `canvas.width` against a CSS-pixel
  `clientWidth`, so at DPR ≠ 1 it fired `setSize()` +
  `updateProjectionMatrix()` on *every* frame. A `ResizeObserver` on the canvas
  now owns resizing. `resize()` returns early on a zero-size canvas (a pane
  hidden by focus mode) *without* recording the size, so the pane re-sizes
  correctly when it reappears; the observer callback then calls `invalidate()`
  unconditionally, because un-hiding a pane restores the CSS size it already
  had — `resize()` finds nothing to do even though the compositor discarded
  the drawing buffer while it was hidden.

**Contract:** any code that mutates a viewer's scene, materials, or clipping
planes from outside `createViewer` **must call `viewer.invalidate()`** — the
change will otherwise not appear until the next camera move. In `index.html`
that means the cross-section toggle, the clip slider, the post-load clip-plane
re-anchor, and `applyClipBBox()`; the handle's own methods (`setModels`,
`clear`, `setFilamentColor`, `replaceGeometry`, `rotate90`, `resetView`)
invalidate internally. `stop()` / `start()` remain the `visibilitychange`
pause/resume pair, and `start()` forces a fresh frame on tab return.

`scripts/test_viewer_invariants.py`'s `RenderBudgetTests` locks all four
properties across `index.html`, `embed.html`, and
`scripts/generate-standalone.py`.

### Security Convention

All dynamic content in `index.html` and `embed.html` that interpolates model
names, filenames, or other data into the DOM uses the DOM API
(`createElement` / `textContent` / `setAttribute`) rather than `innerHTML`.
`innerHTML` is only used for static SVG icons and the gesture-hint overlay
(which contains no user-controlled data). This prevents XSS from
adversarially-named STL files or unexpected `models.json` content.
As a defense-in-depth layer, CI refuses to render any `.scad` file whose
basename contains characters outside `[A-Za-z0-9._ -]` (see step 6 in
[ci-pipeline.md](ci-pipeline.md)).

For **standalone HTML viewers**, `scripts/generate-standalone.py` embeds
filament color data inside a `<script type="module">` block. The
`_load_filament_colors_js()` function uses `json.dumps(name)` to produce a
valid double-quoted JS string literal (handling `"`, `\`, control characters,
and other special sequences), then additionally replaces `<`, `>`, and `&`
with unicode escapes (`\u003c`, `\u003e`, `\u0026`). This prevents a
`</script>` sequence in a color name from terminating the surrounding script
block — an injection vector that would otherwise allow same-origin script
execution in PR preview deployments. Covered by
`scripts/test_generate_standalone.py`.

### Print Time Estimates

A pane holding exactly one model displays a rough print-time badge (e.g., `~25m`, `~1h 30m`)
computed from ADMesh's bounding-box height and volume during CI. The heuristic
uses 0.2mm layer height and 50mm/s speed as conservative defaults. For
near-flat models (`bb_z < 0.5`), a simpler volume-based fallback is used.
The `formatTime()` function formats minutes into human-readable strings. The
badge is omitted if the estimate is unavailable (graceful degradation).

### Printing Notes

A project's `meta.json` can declare an optional `printing_notes` array —
free-text printer/slicer guidance (layer height, seam placement, orientation,
filament choice) that isn't capturable as a structured field. When present,
`index.html` renders a closed `<details class="printing-notes">` block under a
collapsed project-description disclosure in a single-model pane; `embed.html`
renders the same content in a closed `<details>` pinned to the top-right
corner; standalone viewers render one above the footer. All three start
closed (issue #337 — the viewer canvas gets the space instead), and all three
build the notes with
`textContent`/`html.escape` — never `innerHTML` — since the text is arbitrary
free-form content from `meta.json`.

### Model Tree Browser

The sidebar holds a `role="tree"` browser built from `MODEL_INDEX` — a flat
array assembled once from `models.json`, one entry per model, carrying the
project name and data, the model record, its project/model slugs, its
composite descriptor (if any), and a lowercased `haystack` of project name +
model name + tags for filtering.

Each project is a collapsible `treeitem` whose expanded body contains the
project's "Download All", "Download Source", and "View on GitHub" links plus
one `treeitem` button per model. Model buttons carry a 40×30 thumbnail
(`loading="lazy"`, `decoding="async"`, `alt=""`, hidden on error) and the
model's display name, and set `aria-selected` when that model is loaded in
any pane.

Clicking a model loads it into the active pane, replacing its contents.
Ctrl/Cmd-clicking — or clicking with the toolbar's **+ Add to scene** toggle
on — appends it instead. The filter box above the tree matches against
`haystack`; a project stays visible if its own name matches or any of its
models do. Matching projects auto-expand while a query is active and the
previous expansion state is restored when the box is cleared.

Keyboard support follows the tree pattern with a roving `tabindex`:
Up/Down move through visible items, Right expands a project or steps into
its first model, Left collapses or moves to the parent, Home/End jump to the
ends, and Enter/Space activate. `/` focuses the filter box from anywhere.

A `panes` array tracks per-pane state: the pane element and canvas, its
viewer instance, the `MODEL_INDEX` entries it holds, selected filament
colour, cross-section bbox/plane, load token, touch hint overlay, and the
active customizer's teardown function.

### Filament Color Picker

Each pane has a row of 8 circular color swatches (Blue, White, Black,
Grey, Red, Green, Yellow, Orange). The palette is defined in
`filament-colors.json` — a single source of truth shared by `index.html`
(fetched at runtime) and `generate-standalone.py` (injected at build time).
Clicking a swatch updates the Three.js `MeshPhongMaterial` color. The
selected color is stored on the pane and re-applied every time the pane's
models change, so it survives switching models. Composite parts keep their
declared colours and are excluded. White uses `#f5f5f5`
(not pure white) and Black uses `#2a2a2a` (not pure black) to preserve
surface detail under the Phong lighting model.

### Composite Multi-Colour Assembly Previews

STL export is monochrome, so a single merged mesh can't reproduce an
OpenSCAD `color()` preview's per-part colours — and for `nz-ski-fields`, a
full-resolution merged assembly mesh was heavy enough to freeze a CI runner
(issue #272) and crash browsers loading the gallery page. Instead, a
project's `meta.json` can declare an `assembly` object (schema-validated by
`meta.schema.json`, propagated into `models.json`):

```json
"assembly": {
  "stl": "assembly.stl",
  "parts": [
    { "stl": "lake.stl",    "color": "#64b5f6" },
    { "stl": "terrain.stl", "color": "#9e9e9e" },
    { "stl": "snow.stl",    "color": "#f5f5f5" }
  ]
}
```

`stl` names the project STL this composite stands in for; `parts` are
STL/colour pairs that must already be co-registered (share the same origin
and footprint) so they can be loaded into one scene with no offset. Every
viewer computes a `composite` descriptor by matching the model
against `projectData.assembly.stl`, re-validating each part's `color` against
`/^#[0-9a-fA-F]{6}$/` as defence-in-depth even though the schema already
enforces it:

- **`index.html`**: `createViewer()`'s `setModels(entries, token)` treats a
  composite as one entry with several part geometries: it loads every part
  STL with `STLLoader`, computes the union bounding box across the parts,
  centres them on that entry's own origin, and adds one `THREE.Mesh` per
  part — each with its own `MeshPhongMaterial` — into a `THREE.Group`. The
  cross-section toggle iterates `handle.materials` (one material for a
  single model, one per part for a composite) so clipping still applies to
  every part. A pane whose models are all composites **suppresses the
  filament color picker** entirely, since colours are fixed per part, not
  user-selectable.
- **`embed.html`**: unchanged — `createViewer()`'s `loadComposite(parts)`
  does the same thing for its single fixed model.
- **Standalone viewers** (`generate-standalone.py`): `build_composite_js()`
  reads the same `assembly` object from the project's `meta.json` at build
  time, resolves each part's STL to a base64 blob, and serialises
  `COMPOSITE_PARTS` into the generated HTML. The standalone JS scene-setup
  mirrors `index.html`'s `loadComposite()` logic and also skips the color
  picker for composite pages.

`nz-ski-fields/assembly.scad` still exists, but only as the **thumbnail
source** — it renders Z-up (no `rotate([-90, 0, 0])`, unlike the printable
parts) from a downsampled 128px heightmap so OpenSCAD's default camera looks
down onto the coloured terrain for the PNG. Its STL output is no longer
loaded by any viewer.

### 3D Controls

Each pane has a single `.pane-controls-row` below the 3D canvas holding the
"✂ Cross Section" toggle, Rotate X/Y/Z, Reset, and the cross-section depth
slider (plus the ⚙ Customize button when the model ships a parameters
manifest). The buttons are enabled once the pane's models have loaded
(disabled until then); the slider takes the row's leftover width and wraps to
a second line when the pane is too narrow.

- **Rotate 90°** (`Rotate X` / `Rotate Y` / `Rotate Z`): Rotates the mesh 90°
  around the corresponding world axis. Useful for upright models where
  OrbitControls' fixed world-up otherwise prevents free rotation. After
  rotation the cross-section clip bounds are recomputed.
- **Reset**: Restores the camera to its default position and rebuilds the
  controls.

Controls are always `OrbitControls` (with `enableDamping`), imported from
`three/addons/` at Three.js 0.170.0 with no extra import-map entries.
`makeControls()` takes no argument and exists only so `resetView()` can
rebuild the controls — discarding OrbitControls' internal spherical state
along with the camera position — while preserving the current target: it
clones `controls.target`, calls `controls.dispose()`, constructs a fresh
`OrbitControls`, restores the target, and calls `controls.update()`.

The runtime Orbit/Trackball/Arcball mode switcher added in issue #230 was
removed in issue #337: only Orbit was ever used, and the three buttons (plus
the two unused control modules embedded in every standalone viewer) cost
vertical space that the canvas now gets. `scripts/test_viewer_invariants.py`'s
`ViewerChromeTests` locks this — no `TrackballControls`/`ArcballControls`
references, one controls row, no force-opened disclosures.

### Cross-Section View

Each pane has a "✂ Cross Section" toggle button that clips the rendered
contents with a horizontal plane, revealing interior geometry. A depth slider
controls the clip plane position. Pressing `C` toggles the feature via
keyboard for the active pane. Implemented using Three.js local clipping
(`renderer.localClippingEnabled = true`) with a `THREE.Plane` applied to every
material in the pane. When a pane holds several models the plane is anchored
to the union bounding box and clips all of them together — it is a single
world-space cut, not a per-model one. Available in `index.html`, `embed.html`,
and standalone viewers.

### Split Panes & Multi-Model Scenes

The stage toolbar has **1 / 2 / 3** layout buttons (also bound to the `1`,
`2`, and `3` keys). `setLayout(n)` grows or shrinks the `panes` array,
switching `#panes` between `.panes--1/2/3`, which set
`grid-template-columns: repeat(n, 1fr)` (and `grid-template-rows` instead,
below the 900 px breakpoint). Shrinking the layout calls `viewer.dispose()`
on the removed panes — including `renderer.forceContextLoss()` — so cycling
3 → 1 → 3 doesn't exhaust the browser's WebGL context budget.

One pane is the **active** pane (outlined, set by clicking or focusing into
it); tree clicks and keyboard shortcuts target it.

A single pane can hold several models at once. Ctrl/Cmd-clicking a tree
entry, or clicking with the toolbar's **+ Add to scene** toggle on, appends
rather than replaces. `setModels()` centres each model on its own origin,
then lays them out left to right along world X separated by a gap of 15 % of
the widest model, and recentres the row on the origin — so a single model is
framed exactly as it was before. Each loaded model gets a chip above the
canvas: the chip label is a download link, and its ✕ removes that model from
the pane.

Controls that are inherently per-model are shown only when a pane holds
exactly one: the parametric customizer, the QR button, the print-time badge,
the Download STL / Standalone / Source links, the project description, and
the printing notes (the last two are collapsed `<details>` disclosures). The
filament picker, cross-section, view controls, and fullscreen apply to
whatever the pane contains.

### Focus Pane

Each pane has a focus button (top-right, next to fullscreen) that expands it
to fill the stage without using the native Fullscreen API.
`toggleFocusPane(pane)` adds `.pane--focused` to the pane and
`.panes--focused` to `#panes`, which hides the other panes. Pressing `M`
toggles focus for the active pane; `Escape` restores the split layout.

A `ResizeObserver` on each pane's canvas drives `resize()`, so the renderer
self-corrects when a layout or focus change alters a pane's dimensions with no
window resize event (see [Render Budget](#render-budget) — this replaced a
per-frame `canvas.clientWidth` poll).

### Deep Links (URL Hash Routing)

Models are addressable via URL hash. The grammar is:

```
#<pane>[+<pane>...]        panes separated by '+'
   <pane> = <model>[,<model>...]   models within a pane separated by ','
   <model> = <project-slug>[/<model-slug>]
```

`slugify()` normalizes project display names and STL filenames into URL-safe
hyphenated slugs. A slug can never contain `+`, `,`, or `/` — CI restricts
`.scad` basenames to `[A-Za-z0-9._ -]` and `slugify()` only maps `[_\s]+` to
`-` — so the multi-pane grammar is a strict superset of what shipped before:

- **`#<project>/<model>`** (QR codes, shared links) still parses to exactly
  one pane holding one model, and renders identically to before.
- **`#<project>`** (every row of the README gallery table) still resolves to
  that project — it expands and scrolls the project in the tree and loads its
  first model into pane 1.

**Incoming hashes are never rewritten.** `updateHash()` returns early while
`applyingHash` is true, and the initial route holds that flag until every
pane's load has settled, so arriving at `#toothbrush` leaves `#toothbrush` in
the address bar rather than normalising it to `#toothbrush/toothbrush-assembly`
— which would change what users copy out and double-count Plausible hash
pageviews. A hash naming a project or model that no longer exists degrades to
the default view on load with a `console.warn`; the URL is left alone.

`parseHash(raw)` / `formatHash(spec)` are pure functions wrapped in
`// __HASH_ROUTING_START__` / `// __HASH_ROUTING_END__` marker comments so
`scripts/test_hash_routing.mjs` can extract and test the shipped
implementation directly. `parseHash` splits on `+` then `,` and only then
`decodeURIComponent`s each segment (decoding first would let an encoded
separator forge extra panes, and `URLSearchParams` would turn `+` into a
space).

Hash updates use `replaceState` (not `pushState`) to avoid polluting browser
history. The `hashchange` event handles back/forward navigation and ignores
events whose hash matches the last value the viewer itself wrote.

### QR Codes

A pane holding exactly one model shows a QR button (top-right, next to the
focus and fullscreen buttons) that opens a centered popover with a QR code
image linking to the model's deep link URL.
QR PNGs are generated during CI by `qrencode` and stored in `site/qr/`. The
QR images use the site's dark theme colors (`foreground: #E0E0E0`, `background:
#1A1A2E`). The popover is dismissed by clicking outside or pressing Escape.
The `qr` field in `models.json` is only present when the QR file exists,
so the button degrades gracefully.

### Mobile Responsive Layout

Below a 900px viewport width, the app shell switches from "fill exactly one
viewport, no scrolling" to a normally-scrolling page: the sidebar becomes a
fixed off-canvas drawer (toggled by a `#sidebar-toggle` button and a
`body.sidebar-open` class) instead of a permanent column, pane canvases take a
fixed `55vh`/`55dvh` slice of the viewport instead of flexing to fill
remaining space, and the rest of a pane's chrome (chips, colour picker, the
combined controls row, description, printing notes) flows
below the canvas rather than being clipped. Fullscreen mode overrides the
fixed canvas height back to `flex: 1` so a phone in fullscreen still gets the
full screen. `scripts/generate-standalone.py` applies the same fixed-height
media query to standalone viewers. This replaced an earlier fixed-height,
non-scrolling shell where a phone-width pane's chrome could exceed one
viewport height and get silently clipped with no way to scroll (issue #307).

### Touch Gesture Hints (Mobile)

On the first touch interaction on a mobile device, a semi-transparent overlay
appears showing three gesture icons (Rotate, Zoom, Pan) with inline SVGs. The
overlay uses `pointer-events: none` so it doesn't block OrbitControls input.
It fades out after 5 seconds or on the first `touchmove`, whichever comes
first. The hint is shown once per session (`sessionStorage`).

### Accessibility

- **`prefers-reduced-motion`**: a CSS media query disables decorative CSS
  transitions; WebGL OrbitControls are user-driven and intentionally unaffected
- **ARIA attributes**: the sidebar is a `role="tree"` with `role="treeitem"`
  projects (carrying `aria-expanded`) and models (carrying `aria-selected`),
  each project's model list wrapped in a `role="group"`; canvases have
  `role="img"` and an `aria-label` naming every model in the pane; layout,
  focus, fullscreen, QR, colour swatch, chip-remove, and download/source
  controls all have `aria-label` attributes; layout and toggle buttons use
  `aria-pressed`; pane loads are announced through an `aria-live="polite"`
  status region
- **Focus styles**: `:focus-visible` outlines on tree items, buttons,
  swatches, and links; `:focus-within` brings the pane's overlay buttons to
  full opacity
- **Keyboard navigation**: within the tree, Up/Down move between visible
  items, Right/Left expand and collapse, Home/End jump to the ends, and
  Enter/Space activate (Ctrl/Cmd held adds to the pane instead of replacing);
  a roving `tabindex` keeps the tree a single tab stop. Globally, `/` focuses
  the filter box, `1`/`2`/`3` set the pane layout, and — targeting the active
  pane — `F` toggles fullscreen, `D` triggers download, `C` toggles
  cross-section view, `M` toggles focus-pane, and `R` triggers the customizer
  Re-render button (when one is present). `Escape` un-focuses a pane, closes
  the mobile sidebar, or dismisses the QR popover. Modifier keys and input
  fields are excluded from the global shortcuts.

## Embed Viewer (embed.html)

A minimal single-model 3D viewer designed for iframe embedding via OEmbed.
Reads `#<project-slug>/<model-slug>` from the URL hash, resolves it against
`models.json`, and renders the model full-viewport with the same Three.js
scene setup as `index.html` (background `#0f3460`, `MeshPhongMaterial` blue,
3-light rig, OrbitControls with damping). Includes a small "Open in viewer"
link (bottom-right) that opens the full gallery. Has `<meta name="robots"
content="noindex">` to avoid search indexing. A 10-second timeout detects
CDN load failures and shows a fallback error message. Pauses rendering when
the tab is hidden via `visibilitychange`.

## Standalone HTML Viewers

CI generates one self-contained HTML file per model at `site/standalone/`.
Each file inlines Three.js (as base64 data URIs in the import map) and the
STL data (base64-encoded), requiring **no external dependencies** — works
from `file://` or any static host. Generated by `scripts/generate-standalone.py`,
which downloads Three.js 0.170.0 once, verifies SHA-256 hashes, caches
assets locally (`.cache/threejs/`), and uses the same scene setup (colors,
lighting, camera) as the main viewer. Includes a filament color picker and
fullscreen button.

## Public Source Links

Every single-model pane in `index.html`, the "Open in viewer" overlay in
`embed.html`, and the footer of each standalone viewer link back to the
model's `.scad` source in the **public mirror** at
`https://github.com/stjohnb/3d-models` (not the private
`St-John-Software/3d-models` repo), e.g.
`https://github.com/stjohnb/3d-models/blob/main/power-workshop/drill_bit.scad`.
Each project node in `index.html`'s tree browser also gets a "View on
GitHub" link to its source directory (`tree/main/<dir>`). `index.html` and `embed.html` derive the
link from `models.json`'s `files[].source`; `generate-standalone.py` derives
it from `site/.scad-map`'s third (source-path) column. Source paths are
percent-encoded per path segment (never the `/`) since a small number of
`.scad` filenames contain spaces.

**Invariant**: the `PUBLIC_REPO` constant and `publicSourceUrl()` helper must
stay textually identical across `index.html`, `embed.html`, and
`scripts/oembed_helpers.py` (`PUBLIC_REPO_URL` / `public_source_url()`) — the
same class of three-location sync rule as `slugify()`.

## OEmbed Endpoints

Static OEmbed JSON files are generated per model at
`site/oembed/<project-slug>/<model-slug>.json`. Each is a standard OEmbed
v1.0 "rich" type response with an `<iframe>` snippet pointing to
`embed.html#<project>/<model>`. The iframe uses `sandbox="allow-scripts
allow-same-origin"` for security. `<link rel="alternate">` discovery tags
are injected into `index.html`, but since all tags live in a single page,
auto-discovery only works for the site root — not for individual model deep
links (hash fragments aren't sent to the server). For per-model OEmbed,
consuming platforms should be configured with explicit endpoint URLs.

## Analytics

`index.html` and `embed.html` load a self-hosted Plausible script with the `file-downloads`, `hash`, `outbound-links`, `pageview-props`, and `tagged-events` extensions. The `hash` extension makes the viewer's `#project-slug/model-slug` deep links register as distinct pageviews. The `file-downloads` extension auto-tracks STL and zip download clicks. Standalone viewers (`site/standalone/`) intentionally omit the analytics script to remain self-contained and work offline.
